# ADR-004: Clean Architecture'ın Benimsenmesi

## Durum
Kabul Edildi

## Tarih
2026-05-26

## Bağlam
HaberBot ölçeklendikçe veritabanımızı (örn. MongoDB'ye), yapay zeka sağlayıcımızı (örn. Claude'a) veya web framework'ümüzü değiştirebiliriz. Temel iş mantığımızın dış altyapı değişikliklerinden etkilenmemesini sağlamak istiyoruz.

## Karar
Go backend'i için Clean Architecture (Ports & Adapters / Hexagonal Architecture) uygulanması.

## Yapı
- **Domain (`internal/domain/`)**: Varlıkları (Entities) ve arayüz tanımlarını (Ports) içerir. Dış bağımlılık yoktur.
- **UseCase (`internal/usecase/`)**: İş mantığını yönetir (Orchestrates). Sadece Domain'e bağlıdır.
- **Adapter (`internal/adapter/`)**: Domain portlarını (Repositories, Gateways, Fetchers) ve UI işleyicilerini (HTTP Controllers) uygular (Implements).
- **Infrastructure (`internal/infrastructure/`)**: Her şeyi birbirine bağlar (DI Container, Router, DB bağlantısı).

## Sonuçlar
- **Artıları:** 
  - Yüksek test edilebilirlik. DB veya yapay zeka sağlayıcısını kolayca taklit edebiliriz (mock).
  - Tam ayrışma (decoupling). Fiber'ı standart `net/http` ile değiştirmek UseCase'leri veya Domain'i etkilemez.
- **Eksileri:**
  - Daha fazla ortak (boilerplate) kod. Basit CRUD işlemleri birden fazla katmanı geçmeyi gerektirir.
  - Yeni geliştiriciler için daha dik bir öğrenme eğrisi.
